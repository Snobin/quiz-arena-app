The system

Who owns what

Every piece of data has exactly one service that writes it. Services talk to each other through events, with one exception: the game service asks the core service for a question set when a match starts. Select a box to see what it owns and which decisions govern it.

The core loop

One Quick Match, step by step

Each live match is a single actor inside the game service. It handles one event at a time (an answer, a timer tick, a disconnect), so a timer firing and an answer arriving at the same instant can never conflict. Nothing touches the database until the match ends.

Scoring

Faster correct answers score more

Every mode, and every bot, uses one shared scoring function. The server measures time from the moment it sent the question to the moment the answer arrived; the phone's clock is never trusted.

score = correct ? 500 + round(500 × remainingMs ÷ 15000) : 0

Still open

Questions and deferred work

Open questions

  • What India's DPDP Act requires for deleting accounts and data.
  • How to count "coaching centers using Battle Room" when there is no center account yet.
  • OVHcloud's India bandwidth cap (10 Mbps after the monthly quota).

Deferred on purpose

  • Phone OTP sign-in. It's required, but waits until the SMS budget allows (about ₹5 per OTP). The login code leaves room for it.
  • Running more than one game server. That needs routing by match id.
  • Saving matches mid-play so they survive a crash.
  • A staging environment, until a second person joins.
  • Phase 2: district leaderboards, coaching dashboard, weak-topic reports.
